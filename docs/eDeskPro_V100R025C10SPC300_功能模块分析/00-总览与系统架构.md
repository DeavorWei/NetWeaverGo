## 3. 技术栈与运行模型

| 维度 | 实现 |
|---|---|
| 前端 | Electron + Vue（`nmotplatformwebsite` / `nmotcollectappwebsite`） |
| 后端 | Java（Spring Boot 3.5 / Tomcat 10.1）多 WAR 微服务，REST 前缀 `/rest/nmot/*` |
| 脚本执行 | **Python(Jython)** 经 `nmotbusinesscbb` 引擎执行；SNMP 回调端口 **UDP 38887**（CBB 内部，非独立 Jython 服务，详见 `04` §8） |
| 设备协议 | **`lib/nmotprotocolcbb-*`（10 jar，260 类）**：SSH=`Apache MINA SSHD 2.18.0`、SNMP=`snmp4j 2.8.18`、Telnet/CLI/MML 自研、终端仿真 116 类；另有 `netcareinside-sdk`↔桌面客户端 REST 通道（端口 51943） |
| 解析引擎 | 声明式 XML 正则规则（`parsecfg/xmlconfig/<vendor>/*.xml`）+ 字段算子 ETL |
| 存储 | 关系型（H2/MySQL，由 `dbScript/` 建模）+ 文件（NIC 压缩包、CSV 报表） |

## 4. 两大 Python 生态（移植最该分清的）

1. **`product/Script/`** —— 历史**采集脚本库**，由 `CollectItem/*.xml` 注册表驱动，单脚本做「发命令→正则取值→回写」。
2. **`services/EMTMessageAnalyseClientService/`** —— 独立且更大的**配置审计规则引擎**：
   - `app_data/script/<功能>/rule_*.py`：审计规则，导出 `check()`（BGP/OSPF/QOS/MPLS/L2/L3VPN/CLOCK/...）。
   - `collectscript/huawei/<族>/*.py`：采集器，导出 `collect()`，写入结构化 `model` 树。
   - `app_data/pdk/`：公共框架（CmdEchoParser / ParserTool / NeAssistant）。
   - 这是**真正可搬的"规则知识库"**，比 `product/Script` 更系统、按协议功能分类。

## 5. 端到端数据流

```
设备(SSH/Telnet/Netconf/SNMP)
   │  NMOTBusinessService 构造连接参数 (BuildSSHData...)
   ▼
协议组件（位于桌面客户端二进制，非本包 jar）建立会话
   │  下发 CLI 命令（bigCommandConfig.xml 标记大命令流式处理）
   ▼
回显文本
   ├─► product/Script/*.py  (CollectItem 注册表派发) ──┐
   ├─► EMT collectscript/*.py (collect()→model 树)    ├─► 结构化结果
   └─► EMT app_data/script/*.py (check()→CheckResult)─┘
   │
   ▼
IPDeviceCheckService：命令回显 → 正则解析(xmlconfig) → 字段算子 ETL → 按厂商 Saver 落地 DB
   │  + 链路还原(linkrestoration) + 弱光/光模块比对(lowlight) + 交叉光纤(crossconnectedfiber)
   ▼
DB (dbScript 模型)  →  报表导出(Excel/CSV) / 前端展示
```
