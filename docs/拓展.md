## 一、定位判断：它已经是交付工具了，只是没被说破

README 写的是"网络自动化编排与配置集散引擎"，但从能力组合看，它**骨子里就是工程交付工具**，最硬的一条证据在 `docs/功能模块说明书/SNMP查询模块功能和逻辑.md` 的职责边界里：

> 模块**刻意不提供**周期性轮询调度、Trap 值守监听和 MIB 库管理 —— 这些属于长期值守型网管系统的职责，交付工具承担会带来部署负担……

这句话已经把定位说清楚了：**一次性、现场性、产出物导向、弱侵入**。其他能力也都在印证这一点：单设备挂起 + 人工决策（现场应急处置）、离线重放执行器（现场采集、回酒店分析）、内置 SFTP/FTP/TFTP/HTTP（临时给设备喂镜像）、规划比对（验收阶段拿设计稿对现场）。

所以"定位为交付工具"不是转型，而是**把隐含定位显式化，并据此收敛功能取舍**。

### 现有能力 × 交付阶段映射（顺带暴露缺口）

| 交付阶段 | 现有支撑 | 缺口 |
|---|---|---|
| 准备 | 设备资产导入、命令组、ConfigForge 生成配置、文件服务器 | 无"项目"概念，多项目数据混在一库 |
| 上架加电 | SNMP 批量上线确认、批量 Ping | 无 Console/串口、无网段自动发现 |
| 配置下发 | 任务执行引擎、Forge→SendTask、错误挂起干预 | **无 undo/回滚脚本生成、无预检查 dry-run** |
| 验证 | 拓扑采集 + 规划比对（PlanCompare） | 只有链路维度，**配置维度无比对** |
| 备份 | Backup 任务（SFTP 取 running/startup） | 只是落盘，**无版本化、无 diff、无基线** |
| 验收移交 | 执行报告 CSV、比对报告 HTML/CSV/JSON | **无一份汇总的验收报告** |

一句话概括最大的问题：**能力很强，但"最后一公里"没闭环——采集、比对、备份的结果没有被组装成可交付的产出物。**

## 二、未来拓展的四条主线

### 主线 A：补齐交付闭环（最高 ROI，直接强化定位）

**A1. 配置基线管理与漂移对比**
`internal/taskexec/backup_executor.go` 目前只把配置文件落盘。应加：备份版本化（设备+时间+SHA256，拓扑模块已有 `FactHash` 可直接抄）、任意两版本 diff、与"标准基线模板"比对。PlanCompare 的 `makeUndirectedEndpointKey` / 差异分类（`missing_link`/`interface_mismatch`）这套思路完全可以平移到配置项上。
> 低成本捷径：备份目录直接 `git init + commit`，版本 diff、回滚、 blame 全白送，比自研划算。

**A2. 合规/基线检查（Compliance）**
`docs/功能模块说明书/任务执行模块功能和逻辑.md` 第 8.1 节的扩展示例写的就是 `ComplianceTaskCompiler` —— 设计者已经预留了这个位置。用规则组（必须包含/禁止出现/正则匹配）跑 `display current-configuration`，产出 PASS/FAIL 清单 + 修复建议。这比人眼看回显高效一个数量级，且是验收报告的核心内容。

**A3. 一键交付报告生成器**
把"任务执行结果 + 拓扑图 + 规划比对 + 备份清单 + SNMP 资产 + 合规结果"汇总成一份带项目名、阶段、工程师签名位的 HTML/PDF。现在这些产出散落在 `execution/reports`、`plancompare` 导出、拓扑图三处，交付时得人工拼。

**A4. 变更工单与回滚**
下发前自动：预检查（备份当前配置、比对版本）→ 生成 undo 命令序列 → 下发 → 验证 → 失败自动执行 undo。改配置最怕回不去，这决定了敢不敢用工具做批量变更。

**A5. 设备验收清单（Checklist）**
版本、序列号(ESN)、license、电源/风扇/温度、光模块、堆叠/IRF 状态批量采集并自动判定达标。CLI 解析模板 + SNMP 双通道都已具备，华为画像里已经有 `esn` 命令。

### 主线 B：扩大现场覆盖率（降低"到了现场用不了"的风险）

- **厂商扩展**：目前只有 huawei/h3c/cisco（`internal/config/device_profile.go`）。锐捷、中兴在园区网交付中占比极高，建议优先补。设备画像 + `parser/templates/builtin/*.json` 都是模板驱动，且 `ParserManager.ReloadVendor()` 已支持热重载——新增厂商成本可控，甚至可以做成"用户导入解析模板"。
- **协议扩展**：`connutil.ConnectionFactory` 是现成扩展点。优先级：Serial/Console（设备没 IP 时的唯一手段）> NETCONF/RESTCONF > SSH 到 Linux/服务器。
- **设备自动发现**：网段扫描（ICMP → SNMP 指纹 → SSH 探测）自动填充资产库。三件套（`icmp`、`snmp`、`sshutil`）都现成，组合一下即可，省掉手工录几百个 IP。

### 主线 C：工程化与团队化（决定能不能从"个人工具"变成"团队工具"）

- **设备凭据加密（安全短板，优先级最高）**：`internal/models/models.go:17` 的 `Password` 是明文落主库的，只有 SNMP 凭据做了 AES-256-GCM（`internal/snmp/crypto.go`）。交付工程师一台电脑跑多个客户项目，这个风险很实在。复用 `crypto.go` 即可，加主密码解锁。
- **项目/工作区隔离**：设备、命令组、任务、备份、报告按项目隔离，整体导出成一个 `.nwproj` 包（含凭据、模板、历史）。现在全局一个库 + 一个 storageRoot，多项目必然打架。
- **模板沉淀与共享**：命令组已有导入导出，应扩展到解析模板、合规规则、Forge 模板，形成"交付模板包"并版本化——这才是团队资产。
- **离线重放产品化**：`replay_executor.go` 已有能力，缺 UI 入口和"离线数据包"导出。现场采集、离线分析是交付场景的杀手锏，值得重点打磨。
- **失败设备重跑**：`view_models.go` 已有 `FailedDevices` 列表，但没看到"仅重试失败设备"的入口。现场几乎是必用功能，成本极低。
- **回显智能解读**：现在靠人眼盯 `VirtualLogTerminal`。可做规则化异常统计 + 风险提示（错误关键字、接口 CRC/error 增量）。

### 主线 D：平台化（建议克制）

多用户/权限、服务端模式（`task build:server` 已有雏形）、审计日志、ITSM 对接。这些是"网管平台"的方向，容易把工具拖重。**建议只做有强交付诉求的部分**：审计日志（谁在什么时候改了什么配置，验收举证需要）、Git 集成（配置即代码）。

## 三、一批"小而实用"的功能（现场天天用，成本却很低）

| 功能 | 价值 | 可复用的现有资产 |
|---|---|---|
| 一键体检（Ping + SSH + SNMP 三合一，红黄绿矩阵） | 上架前 5 分钟确认全网可达性 | `icmp`、`sshutil`、`snmp.Querier` |
| 配置跨设备搜索（找某个 VLAN/ACL/静态路由在哪台设备） | 排查效率翻倍，交付收尾高频 | 备份文件 + 任务执行原始输出 |
| 端口台账/接线表导出（拓扑 → Excel） | 交付必交文档，现在要手敲 | `task_topology_edges` + 接口事实 |
| **MAC/IP 定位**（给定 MAC 或 IP 反查设备+端口） | 现场查终端接在哪，最高频 | 已解析入库的 FDB/ARP 事实，几乎现成 |
| 批量改密码/建账号（带审计） | 交付收尾安全加固 | 任务引擎 |
| 标准基线下发（NTP/日志主机/SNMP/AAA 一键套用） | 每个项目都要做的收尾动作 | ConfigForge + 任务组 |
| 光模块 & 接口错误统计巡检 | 交付验收的硬件健康证明 | 接口事实 + 解析器扩展 |
| 报告导出脱敏 | 报告要发给客户，日志脱敏器已有但没接到导出链路 | `logger/sanitizer.go` |

其中 **MAC/IP 定位** 和 **端口台账导出** 是最典型的"数据已经躺在库里，只差一层查询"的功能，投入最小、感知最强。

## 四、取舍红线（守住交付工具，不滑向 NMS）

- **不碰**：7×24 轮询、Trap 值守、性能趋势、告警、大屏、MIB 浏览器（SNMP 文档已明确划界，这个决策是对的，别退让）
- **坚持**：零部署（单 exe）、一次性、数据可带走、以"产出物"为中心、可解释可举证（拓扑决策轨迹 `TopologyDecisionTrace` 这套设计非常契合交付举证，应保持并推广到配置变更领域）

## 五、落地路线建议

**近期（低成本高感知）**
1. 设备凭据加密 + 项目工作区隔离
2. 备份版本化 + 两版本 diff（借 Git，最快）
3. 一键交付报告（HTML/PDF 汇总）
4. 失败设备重跑 + MAC/IP 定位 + 端口台账导出

**中期（构壁垒）**
5. 合规/基线检查编译器（文档里已经画好了扩展点）
6. 变更工单 + undo 自动生成
7. 厂商扩展（锐捷、中兴）+ Console 串口
8. 设备自动发现 + 验收清单（ESN/license/光模块）
9. 离线重放 UI 化 + 离线数据包

**远期（可选）**
10. 团队/服务端模式、审计日志、模板市场、AI 辅助回显解读
