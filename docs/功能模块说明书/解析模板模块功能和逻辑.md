# 解析模板模块功能和逻辑

## 1 模块概述

解析模板模块是 NetWeaverGo 的**核心数据结构化提取底座**。它将网络设备通过 CLI 执行产生的非结构化文本回显（Echo），转换为标准的关系型表格行数据（`[]map[string]string`），供下游的拓扑推断、巡检合规核对、设备资产建档和交付报告使用。

在 P0 阶段，本模块完成了**断头路 #2、#3 的全面接通**，并引入了基于华为 eDesk Pro 优秀算法演化而来的**声明式二维规则树引擎（`EngineTree`）**，彻底打破了以往仅支持一维单行正则的局限，使复杂的嵌套表格型回显无需编写任何 Go 代码即可通过纯配置实现自动化提取。同时，经过极为严格的工业级代码审计，本模块已实现全字段数据防破坏、编译期只读并发安全、快照失败自动回滚与 100% 真实回显测试覆盖。

### 1.1 架构位置

```
前端 ParseTemplates.vue (解析模板工作台: 表格/JSON多视图、边改边测 Live Test、标识锁定保护)
  → frontend/src/services/parseTemplateApi.ts
  → Wails 绑定 internal/ui/parse_template_service.go (ParseTemplateService) [断头路#3接通]
      ├── 事务保护与热重载回滚 (若快照 Reload 失败自动回滚 DB)
      ├── 字段防破坏机制 (保留非编辑引擎已有数据，绝不向 DB 写入 "null")
      → internal/repository.ParseTemplateRepository (读取 net_user_parse_templates) [断头路#2接通]
      → internal/parser.ParserManager.ReloadVendor(vendor) (合并内置模板与用户模板)
          → internal/parser.CompileTreeRules(rules) (拓扑无环校验 + 正则预编译 + 编译期固化 IsPath)
          → internal/parser.NewCompositeParser (原子替换只读快照)
              → EngineRegex: internal/parser.RegexParser
              → EngineAggregate: internal/parser.AggregateEngine
              → EngineTree: internal/parser.TreeEngine (二维规则树引擎，纯只读无竞态)
                  ├── block_splitter.go (SplitBlocks, 保持块头与尾块收敛)
                  └── result_tile.go (TileResultTree, 属性继承、笛卡尔积展开与字段补齐)
```

### 1.2 支持的引擎能力矩阵

| 引擎类型 | 标识 | 核心模型 | 适用回显场景 | 复杂度 |
|---|---|---|---|---|
| **纯正则引擎** | `regex` | 单正则命名组/索引提取 | 简单单行事实（如 `display version` 提取版本号/主机名） | 极低 |
| **聚合状态机引擎** | `aggregate` | RecordStart + 捕获规则 + Filldown | 多行跨行记录（如 `display eth-trunk`、简单接口摘要） | 中等 |
| **二维规则树引擎** | `tree` | **ParentItem + SplitRegex + 编译期 IsPath 拍平** | **多层嵌套、父子块、分块表格（如 `display device`、`display interface` 详显、`display vlan`）** | 高表达力、零代码 |

## 2 核心数据结构与并发安全

### 2.1 规则树配置模型（`internal/parser/tree_rules.go`）

```go
// TreeRule 声明式解析规则（对齐 eDesk Pro ParseRule 体系）
type TreeRule struct {
    ParseItem    string `json:"parseItem"`    // 字段名（主键）
    ParentItem   string `json:"parentItem"`   // 父字段名；空字符串表示根规则
    IsList       bool   `json:"isList"`       // 是否为列表节点（分块或多匹配）
    ItemType     string `json:"itemType"`     // string | number
    ParseRegex   string `json:"parseRegex"`   // 取值正则
    ParseFlags   string `json:"parseFlags"`   // "m" / "i" / "mi" → 自动拼接内联标志 (?mi)
    GroupIndex   int    `json:"groupIndex"`   // 捕获组序号（缺省为 1）
    SplitRegex   string `json:"splitRegex"`   // 分块正则（用于列表节点切块）
    SplitFlags   string `json:"splitFlags"`   // 分块正则标志
    IsOutput     bool   `json:"isOutput"`     // 是否输出到平铺表格结果
    DefaultValue string `json:"defaultValue"` // 未命中时的默认缺省值（如 "N/A"、"0"）
    Order        int    `json:"order"`        // 执行/排序优先级
}

// TreeTemplate 树形模板配置
type TreeTemplate struct {
    SchemaVersion  string     `json:"schemaVersion,omitempty"` // 模板格式版本
    Author         string     `json:"author,omitempty"`        // 作者
    Tags           []string   `json:"tags,omitempty"`          // 标签
    Rules          []TreeRule `json:"rules"`                   // 规则清单
    MaxOutputLevel int        `json:"maxOutputLevel"`          // 拍平深度（0 表示全部展开）
}
```

### 2.2 编译态与并发只读设计

在早期原型中，`MarkPathNodes` 曾放置于运行时拍平阶段，导致多个 goroutine 并发执行 `Parse()` 时并发修改内存快照中的 `rule.IsPath` 产生 Data Race。
在 P0 最终设计中：
1. **编译期计算固化**：在 `CompileTreeRules` 编译期即通过反向回溯将包含 `IsOutput=true` 的路径标记为 `IsPath=true`；
2. **解析期纯只读**：`TreeEngine.Parse` 在解析和拍平阶段对 `CompiledTreeRule` 完全只读，确保高并发无锁安全；
3. **字段补齐一致性**：在 `TileResultTree` 最终结果输出前，扫描所有声明为 `IsOutput=true` 的规则，若某行未产出该键则自动以 `DefaultValue`（缺省为 `""`）补齐，保证数据行间具有严格对齐的列结构。

```go
// CompiledTreeRule 预编译后的规则（不可变只读结构）
type CompiledTreeRule struct {
    TreeRule
    CompiledParseRegex *regexp.Regexp
    CompiledSplitRegex *regexp.Regexp
    Children           []*CompiledTreeRule `json:"-"`
    IsPath             bool                `json:"-"` // 编译期固化，解析期只读
}
```

## 3 核心算法与处理逻辑

### 3.1 分块切片工具（`internal/parser/block_splitter.go`）

借鉴 eDesk Pro 最完善的 `find_pos_by_pattern` 算法：
1. **保留块头**：由 `keepHeader` 参数控制，保证块头中的槽位号、板卡名完整包含在块体内。
2. **尾块完整收敛**：最后一个块自动切到文本末尾（`echoLen`），不丢失尾部字符。
3. **安全容错**：无匹配时直接返回 `nil`，不触发 Panic。

### 3.2 规则树编译与成环检测（`CompileTreeRules`）

在模板被加载到内存快照前，执行双重防御检查：
1. **正则预编译**：自动将修饰符（如 `m`, `i`）转换为 Go RE2 的内联语法 `(?mi)` 并预编译；
2. **DAG 拓扑无环检查**：使用三色标记法（0:未访问, 1:访问中, 2:已访问）检查父子依赖关系，若发现 `A -> B -> A` 等递归依赖环路，立即拒绝编译并报错；
3. **路径预先剪枝计算**：调用 `markPathNodes` 固化各节点 `IsPath`。

### 3.3 结果拍平与笛卡尔展开（`internal/parser/result_tile.go`）

严格保持 `CliParser.Parse(...) []map[string]string` 契约不变：
1. **路径剪枝**：沿 `IsPath == true` 分支向下展开，剪除无关中间节点；
2. **标量就地合并**：同实体标量属性就地归并；
3. **列表分叉递归**：遇到列表子节点时触发笛卡尔积展开并继承父级属性；
4. **统一列对齐**：最后阶段针对输出规则补齐默认值。

## 4 前后端交互与健壮性保障

### 4.1 服务层健壮性与防破坏机制（`ParseTemplateService`）

1. **防数据覆写破坏 (H1)**：
   在 `UpdateTemplate` 时，仅按当前操作引擎更新对应的数据库字段；未提供的引擎字段和原有配置严格保留，杜绝向数据库写入 `"null"` 字符串覆盖破坏其它引擎配置。
2. **未知厂商支持与优雅加载 (H2)**：
   内置文件若不存在（如用户新增第三方自定义厂商），`loadBuiltinTemplates` 优雅返回空集合而非中断失败；支持纯用户自定义厂商全生命周期管理。
3. **快照热重载失败回滚 (Rollback)**：
   无论是新建还是更新模板，若入库后触发 `ReloadVendor` 编译或解析失败，服务层立即自动将数据库记录回滚至先前的完好状态，保证内存快照与数据库数据 100% 最终一致。
4. **标识不可篡改 (M5)**：
   更新模板接口严格忽略对 `vendor` 和 `commandKey` 的篡改尝试，前端编辑弹窗中对厂商与命令标识锁定置灰（Disabled）。

### 4.2 前端在线工作台功能特性（`ParseTemplates.vue`）

1. **多视图切换 (L4)**：测试面板支持“表格视图 (Table)”与“原始 JSON 树视图 (JSON)”一键切换，方便排查字段细节；
2. **边改边测 (Live Test, M3)**：在新建与编辑弹窗内提供即时自测面板，用户无需保存即可粘贴回显验证当前表单内编辑的正则与规则；
3. **全引擎支持**：支持 `tree`（规则树与拍平深度 `maxOutputLevel`）、`regex`（单条正则与多行匹配）、`aggregate`（聚合状态机 JSON）三类引擎编辑；
4. **字段映射配置**：提供可视化的 `FieldMapping` 重命名配置项；
5. **语法指引 (L2)**：明确标明 Go RE2 规范（如 `(?m)` 多行前缀、命名组 `(?P<name>...)` 规范，提示不支持前瞻后顾）。

- **能力**：
  - 自动遍历扫描指定目录中所有 `.json`、`.py`、`.txt` 文件中的正则表达式；
  - 静态识别 RE2 不支持的语法特征：正向先行断言 `(?=...)`、负向先行断言 `(?!...)`、正向后行断言 `(?<=...)`、负向后行断言 `(?<!...)`、反向引用 `\1, \2`、所有格量词 `*+, ++` 等；
  - 自动输出 Markdown 格式的迁移清单报告（参见 [`docs/不兼容正则迁移清单.md`](file:///d:/Document/GO/NetWeaverGo/docs/不兼容正则迁移清单.md)），为后续规则库维护提供改写建议。
