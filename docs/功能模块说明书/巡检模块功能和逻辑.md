# 设备巡检与合流模块功能和逻辑

## 1 模块概述

设备巡检与交付闭环合流（Inspection Application Layer & Convergence with Delivery Loop）模块是 NetWeaverGo 的**业务应用层核心组件与质量验收结论载体**。

在网络工程日常运维、割接前预检、割接后验收以及交付验收流程中，工程师需要针对大量现网设备（如交换机、路由器、防火墙）执行标准化的巡检检查项，并对采集到的非结构化或半结构化指标（如 CPU 利用率、内存负载、接口丢包与错包、风扇电源环境状态、BGP/OSPF 邻居建立情况）进行规则判定。

本模块全面继承并重构了华为 eDesk Pro 巡检评估体系的思想精华，在 NetWeaverGo 内实现了**纯 Go 原生的高性能独立判定引擎与任务编排执行器**：
1. **统一结论载体（Single Conclusion Carrier）**：全面统一 `ResultCode`（8 项标准状态）与 `Severity`（4 级标准严重度：`blocker`、`major`、`minor`、`info`），作为巡检、A2 合规性审计与 A5 交付验收的统一事实标准；
2. **多模式外置阈值判定引擎（Inspection Engine）**：支持区间合格（`bound`）、区间外合格（`outside`）、数值小于等于（`lte`）、数值大于等于（`gte`）、精准匹配（`equals`）、必须包含（`must_contain`）、禁止包含（`must_not_contain`）及正则表达式（`regex`）；全面支持多行表格（Multi-row table）逐行遍历判定与空阈值主动防御（`TEST_EXCEPT`）；
3. **上下文智能举证与专家建议（Evidence & Advice）**：在指标异常时自动提取 CLI 回显中的命中行及前后 1 行上下文证据（`EvidenceJSON`），并在导出的 CSV（含独立举证列）与前端抽屉中联动呈现；同时注入来自 eDesk Pro 专家知识库的排查指引与处置建议（`Advice`）；
4. **前置采集优先与命令级会话复用（`IsPreCollect` & Session Cache）**：自动将标记为 `IsPreCollect` 的基础信息项排在最优先执行，执行完毕后在单台设备的当前任务会话内缓存原始回显，多项共用命令（如 `display cpu-usage`、`display version`）仅发包一次，大幅提升并发吞吐并杜绝高频命令冲垮网络设备 CPU；
5. **多轮执行严格隔离与最新运行对齐**：执行器入库采用 `(run_id, device_ip)` 联合条件幂等清理，历史任务记录永不丢失；UI 汇总与明细接口默认智能对齐最新批次，彻底杜绝多轮数据交叉混杂；
6. **完整工作台与防乱码导出**：提供多维度可视化看板、矩阵明细、规则库管理，以及带 UTF-8 BOM（`\xEF\xBB\xBF`）的 Excel 兼容 CSV 导出（含举证与上下文）与 JSON 导出。

## 3 巡检判定引擎设计 (`internal/inspection/engine.go`)

巡检判定引擎完全解耦，是一个支持独立单元测试的高性能规则引擎。

### 3.1 输入与输出

- **输入（`EvaluateInput`）**：
  - `RunID` / `DeviceIP`
  - `Item`（检查项定义：字段、判定方式、阈值规则、默认问题与建议、严重度）
  - `RawEcho`（CLI 原始命令回显文本）
  - `ParsedRows`（结构化解析器产生的键值对字典切片 `[]map[string]interface{}`，支持单行与多行表格）
- **输出（`InspectionResult`）**：
  - 包含 `RunID`、`DeviceIP`、`ItemCode`、`ItemName`、`Category`、`Status`、`Severity`、`ActualValue`、`Problem`、`Advice`、`EvidenceJSON` 等标准落库字段。

### 3.2 判定算子体系与多行表格遍历

| 判定方式 (`checkType`) | 支持的算子 (`rangeType` / 匹配规则) | 判定通过条件 (PASS) | 多行表格语义 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| `threshold` | `lte` (Less Than or Equal) | 提取数值 $\le MaxValue$ | 全行遍历：任一行超出上限即触发不通过，记录超标行 | CPU 利用率 $\le 80\%$、板卡温度 $\le 65^\circ\text{C}$ |
| `threshold` | `gte` (Greater Than or Equal) | 提取数值 $\ge MinValue$ | 全行遍历：任一行低于下限即触发不通过 | 供电电压 $\ge 48\text{V}$、运行时间 |
| `threshold` | `bound` (区间闭合合格) | $MinValue \le \text{数值} \le MaxValue$ | 全行遍历：所有行必须均在区间内 | 环境温度 $10^\circ\text{C} \sim 45^\circ\text{C}$ |
| `threshold` | `outside` (区间外合格) | $\text{数值} < MinValue$ 或 $\text{数值} > MaxValue$ | 全行遍历：任一行落入禁区即触发报警 | 异常偏离区间监控 |
| `threshold` | `equals` | 字段值与 `DefaultValue` 严格一致 | 全行遍历：所有行均须相等 | 风扇状态等于 `Normal` |
| `must_contain` | 字符串包含 | 回显或字段包含指定关键字 | 至少一行包含目标关键字即视为通过 | 接口状态含 `UP`、BGP 会话含 `Established` |
| `must_not_contain` | 字符串排除 | 回显或字段严禁出现关键字 | 全行遍历：任一行出现违规词即判定失败并标记行号 | 风扇/电源严禁含 `Abnormal`、接口严禁含 `Error-Down` |
| `regex` | 正则匹配捕获 | 满足正则模式匹配 | 匹配回显或表格行 | 软件版本格式校验、时钟同步提取 |

#### 3.2.1 空阈值防御（Empty Threshold Defense）
若检查项的 `CheckType` 为 `threshold`，但未配置有效阈值规则（`ThresholdsJSON` 为空或各阈值区间值均为空），判定引擎主动返回 `TEST_EXCEPT`（异常状态），并在问题说明中明确提示配置缺失，杜绝隐式误判为通过。

#### 3.2.2 多行表格深度评估
针对风扇模块（`display fan`）、电源模块（`display power`）、接口列表（`display interface brief`）等产生多行解析结果的命令，引擎通过 `extractAllFieldValues` 遍历所有数据行：
- `must_not_contain`：扫描每一行，一旦检测到违规值（如第 2 行风扇 `Abnormal`），立即判定 `TEST_FAIL` 并精确记录 `行 2: Abnormal`；
- `threshold`：扫描每一行数值，记录最劣值或超限行号（如多单板中最高温度超过 $65^\circ\text{C}$ 的具体单板）；
- 杜绝传统引擎仅检查首行导致后续行硬件故障漏判的重大缺陷。

### 3.3 上下文智能举证（Contextual Evidence Extraction）

当检查项判定为未通过（`TEST_FAIL` 或 `TEST_WARNING`）时，引擎执行举证定位：
1. 精准定位回显文本中出现敏感关键字、正则模式或阈值字段的行；
2. 提取该行及前后各 1 行（$\pm 1$ line）的上下文内容，还原故障现场真实信息；
3. 序列化为 JSON 数组写入 `evidence_json`；
4. 导出 CSV 报表时在独立列 `"举证追踪与上下文 (Evidence)"` 中换行呈现，方便技术专家离线核对。

## 4 统一结论规范与交付闭环合流

为了与未来 A2 合规性审计与 A5 交付验收无缝合流，本模块在 `internal/inspection/result.go` 中定义了标准映射协议。

### 4.1 统一测试结果状态 (`ResultCode`)

```go
const (
	ResultPass     ResultCode = "TEST_PASS"     // 测试通过
	ResultFail     ResultCode = "TEST_FAIL"     // 测试失败
	ResultWarning  ResultCode = "TEST_WARNING"  // 告警/轻微不符
	ResultUnaccord ResultCode = "TEST_UNACCORD" // 与规划不一致
	ResultIgnore   ResultCode = "TEST_IGNORE"   // 忽略检查
	ResultExcept   ResultCode = "TEST_EXCEPT"   // 异常错误（超时/断连/配置缺失）
	ResultManual   ResultCode = "TEST_MANUAL"   // 需人工确认
	ResultUntest   ResultCode = "TEST_UNTEST"   // 未执行
)
```

### 4.2 统一严重度与映射协议

```go
const (
	SeverityBlocker SeverityLevel = "blocker" // 致命：导致验收受阻或业务不可用
	SeverityMajor   SeverityLevel = "major"   // 严重：存在功能缺失或重要隐患
	SeverityMinor   SeverityLevel = "minor"   // 一般：轻微告警或次要配置差异
	SeverityInfo    SeverityLevel = "info"    // 提示：仅供记录与展示
)
```

**严重度映射规则**：
- `blocker`（致命）：映射为 `TEST_FAIL`（严重度 `blocker`）；
- `major`（严重）：映射为 `TEST_FAIL`（严重度 `major`）；
- `minor`（一般）：映射为 `TEST_WARNING`（严重度 `minor`）；
- `info`（提示）：映射为 `TEST_PASS`（严重度 `info`）；
- **防御性兼容**：支持历史别名 `"critical"` 自动安全映射为 `SeverityBlocker`，并输出警告日志引导规范。

### 4.3 汇总指标模型 (`InspectionSummaryVO`)
支持完整的 8 态指标统计与设备级别健康聚合：
- `totalDevices` / `passDevices` / `warnDevices` / `failDevices`；
- `totalItems` / `passItems` / `failItems` / `warnItems` / `exceptItems`；
- `ignoreItems` / `manualItems` / `untestItems` / `unaccordItems`；
- `blockerCount` / `majorCount` / `minorCount` / `infoCount`。

## 5 内置模板与专家知识库种子

系统启动时在 `internal/inspection/seeds.go` 中自动装载 4 套内置模板及 12 条高价值检查规则：

1. **`tpl-huawei-general` (华为数通通用日常健康巡检模板)**：
   - `GEN_CPU_USAGE`：主控板 CPU 使用率 $\le 80\%$ (Major)
   - `GEN_MEM_USAGE`：设备内存占用率 $\le 85\%$ (Major)
   - `GEN_TEMPERATURE`：单板环境温度 $\le 65^\circ\text{C}$ (Major)
   - `GEN_FAN_STATUS`：风扇状态严禁包含 Abnormal (Blocker)
   - `GEN_POWER_STATUS`：电源供电状态严禁包含 Abnormal (Blocker)
   - `GEN_DEVICE_UPTIME`：持续运行时间必须包含 uptime is (Minor)
   - `GEN_INTERFACE_ERRORS`：接口错包严禁包含 Error-Down (Minor)
   - `GEN_NTP_SYNC`：NTP 时钟同步必须包含 synchronized (Minor)
2. **`tpl-huawei-ce` (华为 CloudEngine 数据中心交换机深度巡检模板)**：
   - `CE_CPU_USAGE`：数据中心核心 CPU $\le 75\%$ (Major)
   - `CE_BGP_PEER`：BGP/EVPN 邻居状态必须包含 Established (Blocker)
3. **`tpl-huawei-s` (华为 S 系列园区交换机巡检模板)**：
   - `S_STP_STATUS`：生成树环路保护严禁包含 DISCARDING (Major)
4. **`tpl-huawei-ar` (华为 AR 系列路由器网关模板)**：
   - `AR_OSPF_NEIGHBOR`：广域网 OSPF 邻居状态必须包含 Full (Blocker)

所有异常规则均附带标准化的 **eDesk Pro 专家修复建议（`advice`）**，明确提示运维人员排查步骤。

### 5.1 多语言文案种子（报表级 i18n）

`EnsureInspectionItemTextSeeds` 幂等装载 `inspection_item_texts`（`key` + `locale` 唯一索引）：

- **Key 必须与 `InspectionItem.Code` 一一对应**（如 `GEN_CPU_USAGE`、`CE_BGP_PEER`），否则导出时无法命中；
- 当前覆盖 4 套内置模板全部 12 个检查项的 `en-US` 文案（Name / Description / Advice）；
- 中文导出直接复用 `InspectionResult` 原文，不重复维护 `zh-CN` 文案；未命中文案的条目自动回退原文；
- 种子以 `(key, locale)` 做 `OnConflict DoUpdates`，可重复执行（幂等）。

### 5.2 检查项分组树（`templates.groups`）

- 模型：`InspectionGroups`（`InspectionGroup{Code, Name, Children, ItemCodes}`）以 `serializer:json` 落入 `inspection_templates.groups` 可空列，旧记录为 `nil`；
- 用途：报表与前端展示的**分层归类**（`Category` 的等价物），**不改变检查项执行顺序与判定逻辑**；
- 前端：`components/inspection/InspectionGroupTree.vue` 提供分组增删、归属检查项选择、父级移动（排除自身子树以防成环），整树提交并持久化。

## 6 报表导出设计（防乱码、上下文举证与多语言）

巡检报告导出支持两种标准格式：
1. **CSV 报表**（`inspection.ExportInspectionResultsCSV`）：
   - 在流的起始字节写入 **UTF-8 BOM 头**（`\xEF\xBB\xBF`）；
   - 完全解决 Windows 简体中文版下 Microsoft Excel 打开 CSV 文件中文字符变成乱码的经典痛点；
   - 包含列：设备 IP、巡检项编码、巡检项名称、分类、状态、严重度、实际采集值、基准阈值、问题详述、专家处置建议、**举证追踪与上下文 (Evidence)**、评估时间戳。
2. **JSON 结构化报表**（`inspection.ExportInspectionResultsJSON`）：
   - 输出包含完整字段及原始上下文 JSON 数组的格式化报表，便于与上层监控或工单平台对接。
3. **多语言导出**（`...WithLocale` 变体）：
   - `locale` 为空或 `zh-*` 时输出中文，与旧行为**完全一致**（原函数保留为默认包装，零破坏）；
   - `locale = en-US` 时：CSV 表头本地化（Device IP / Item Code / ...），并按 `InspectionItem.Code` 命中 `inspection_item_texts` 替换检查项名称与处置建议；
   - 未命中文案的条目一律回退中文原文；导出前仍执行 `ValidateExportContent` 脱敏阻断（红线）。
